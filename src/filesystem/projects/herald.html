HERALD — Changelogs People Actually Read Role: Founder Website: sendherald.com Your users should know what you just shipped. We kept shipping things nobody knew about. Writing release notes was a Friday afternoon chore, so it mostly didn't happen, and work that shipped may as well not have. Every tool I looked at either didn't talk to GitHub or charged by monthly active users, which means your bill grows every time you succeed. So I built Herald. Connect GitHub once and it reads your merged PRs, drafts the changelog, and puts it in front of the people who actually care. What It Does:  GitHub-native — Pulls real shipped work straight from merged PRs.  AI drafting — Turns commits and PRs into release notes a human wants to read.  Actually delivered — Publishes where users see it, instead of a page nobody visits.  Segmented — Internal users, client users, and beta releases can each see their own view. Running On It: Herald publishes its own changelog, and it hosts Omarchy's real release history. Cortex (agency project and client management) and Nebula (media operations) run on it too. // built the thing I wanted, then made everything else use it.
